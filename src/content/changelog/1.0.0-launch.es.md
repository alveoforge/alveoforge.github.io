La primera versión pública de AlveoForge: backends Java (Spring Boot 4.1) listos para producción generados desde tu schema SQL. Lo que entrega la v1.0, para cada entidad de cada schema:

### Arquitectura

- Arquitectura hexagonal real (ports & adapters) con un vertical slice autocontenido por entidad, con el dominio aislado de la base de datos, el framework y el delivery.
- Generación determinista: el mismo schema produce siempre la misma estructura. Auditas una vez y verificas cada build.
- Despliega el mismo schema como monolito modular o como microservicios, sin reescritura.
- El código es 100% tuyo: Java estándar y legible, sin dependencia de AlveoForge en runtime.

### Modelo de datos y persistencia

- Cobertura completa de tipos SQL estándar: arrays, enums, JSONB, UUID, timestamptz, precisión numérica, binario, xml/citext, y más.
- Claves primarias compuestas, naturales y autogeneradas; N-N modelado como recurso de primera clase.
- Herencia de tablas y particiones declarativas de PostgreSQL.
- Persistencia multi-store: PostgreSQL, MongoDB opcional, caché Redis, y un outbox transaccional para la propagación entre stores.
- Soft-delete y campos de auditoría (creado / modificado / borrado) gestionados automáticamente.

### Migraciones y bases de datos existentes

- Migraciones versionadas con **Flyway o Liquibase**, a tu elección, con paridad total.
- **Adopción brownfield**: lo apuntas a tu base de datos de producción existente y se adapta, sin reconstruir tu schema.
- Tu DDL es la fuente única de verdad; el esquema se valida contra las entidades al arrancar, así que no hay deriva.

### API

- CRUD completo más operaciones en lote: create-many, by-ids, updates masivos.
- Expand de relaciones al leer (`?expand=`), hasta dos niveles, sin consultas N+1 ni un grafo ORM filtrado.
- Paginación agnóstica al framework con límites de página y lote configurables.
- Documentación OpenAPI / Swagger y validación de la petición en cada endpoint.
- DTOs de respuesta públicos para ocultar campos sensibles.

### Autenticación

- Autenticación JWT (login / register) con refresh tokens y logout.
- Flujo de verificación por email en el registro.
- Funciona en proceso (monolito) o entre servicios (HTTP), desde el mismo modelo.
- Seeding de reference-data y gestión de defaults obligatorios, para una base de datos que arranca limpia a la primera.

### Aseguramiento de calidad

- Suite de tests en una pirámide de cuatro capas (de unit a end-to-end), cubriendo caminos de éxito **y** de fallo (validación, auth, no encontrado, tipo de medio no soportado).
- Tests de integración de base de datos para PostgreSQL y MongoDB.
- 95–100% de cobertura (métodos, líneas, ramas), con informes HTML de tests y cobertura en la entrega.

### Escala y entrega

- Validado en schemas reales de más de 300 tablas.
- Prueba antes de pagar: una instancia en vivo y el Swagger completo, cada endpoint testeable, antes de pagar nada.
- Entregado a un repositorio privado con 30 días de soporte post-entrega; regenerado de forma determinista cuando cambia tu schema.
